# 统计口径与阈值

## 通用口径

- **统计窗口**：默认最近 30 天（与 Claude Code 默认保留期一致）；`--retest` 从上次体检的时间点开始；`--since` 自定义。报告页头同时写“统计窗口”和“实际有记录的起止日期”。
- **会话**：主会话才算；子代理会话单独计数，不计入会话数和消息数，但它们调用的 Skill、MCP 算“用过”。程序调起的会话（Claude Code `sdk-*` 入口、Codex `exec` 来源或 `canvas` / `exec` / `sdk` 类 originator）不计入使用习惯，只在页头报个数。
- **常用项目**：至少 2 个会话或 10 条消息，并且不是应用自动建的目录（Codex App 的 `~/Documents/Codex/<日期>/…`、Claude 桌面版的 scratch 目录、系统临时目录）。规则文件覆盖率（C1）只看常用项目，并列出没有规则文件的那几个。
- **用户消息**：人亲手发的文字。不算斜杠命令、工具结果、系统注入（环境信息、AGENTS.md 注入、任务通知）、压缩摘要。
- **短消息**：去掉首尾空白后 ≤ 6 个字符。
- **改过代码的会话**：改过至少一个非文档文件（`.md`、`.txt`、`.csv`、图片、音视频、Office 文件不算）。B1、B2、B7 只看这类会话，纯写文档的会话不要求跑测试。
- **验证**：在会话里第一次改文件之后，出现测试 / 构建 / lint 命令，或调用了浏览器类工具（截图、点击、读页面）。
- **并行**：把时间切成 30 分钟一片，同一片里都有消息的会话数取最大值。会话开着但不说话不算。
- **缓存命中率**：cache_read ÷ (input + cache_read + cache_write)。Codex 的 input 已含缓存部分，脚本先减掉再算。
- **Skill 装用比**：已安装 = 该产品会加载的 Skill 目录（个人、插件、统计窗口内活跃项目的项目级）按 `name` 去重；用过 = 窗口内被调用过（Claude Code：Skill 工具、`skill_mention`；Codex：读取过某个 `SKILL.md`，或消息里 `$skill` 提及），且属于已安装的那些。

## 结果信号（E 区）

- **返工消息**：用户消息的前 40 个字里，出现“不对 / 不行 / 报错 / 失败 / 还是没 / 不够 / 太糊 / 有点粗糙 / 你是不是搞错了 / 重做 / 回滚”这类说法（中英文）；排除“没问题 / 太棒了 / 我说错了”这类正面或自我更正的说法；条件句和提问（“如果…不够”“是否…”）除非带“报错 / 失败 / 不对 / 不行”等强信号，否则不算。
- **准确度**：在作者 1500 多条消息上抽样，准确率约八成，召回率估计七成左右。所以它适合看**比例和趋势**、做前后对比，不适合逐条当真。
- **E1 返工率**：返工消息 ÷ 用户消息 × 100。报告同时给出统计窗口前半段和后半段的值，看在变好还是变差。
- **E2 一次做对**：3 条消息以上的会话里，从头到尾没有返工消息的占比。
- E 区判定显示为“表现好 / 偏弱”，不说“做对了 / 用错了”。

## 打分

- 判定：good 1 分，unused 0.3 分，bad 0 分；na（数据不足）和 info（仅供参考）不计分。
- 一项检查涉及多个 Agent 时，按各自会话数加权。只体检配置、没有会话的 Agent（如 Cursor）只显示判定，不计分。
- 分区分 = 区内检查项按权重平均；总分 = A 25% + B 25% + C 20% + D 10% + E 20%。
- 信号较弱的检查（B3 提示词长度、B4 打断、D1 模型分档）照常展示判定，但不计分。B6（Agent 向你提问）和原 D3（并行）移到功能雷达，只展示次数。
- 会话少于 5 个或消息少于 30 条时不出总分。

## 证据

每张卡片除了数值，还给出“是哪几个会话 / 项目”：最长的会话（A1）、压缩最多的会话和跨天会话的贡献（A2）、没验证的改代码会话（B2）、没有规则文件的常用项目（C1）。项目一律用代号，日期精确到天。

## 数字核对

模型写的总评里，每个数字都要能在 `findings.json`、会话总数或统计窗口里找到。不拿整份 `facts.json` 核对，因为里面成千上万的 token 数会让编造的数字碰巧“对上”。

## 校准记录

**2026-10-26，作者本机 30 天数据**（Claude Code 47 个会话、Codex 103 个会话）：

- B2 起初按“改过任何文件”算，Codex 只有 47%。但很多会话只是在写 Markdown 文章，要求它们跑测试不合理。改成只看“改过代码的会话”后，Claude Code 88%、Codex 50%。
- D3（原 D4）起初按会话首尾时间算重叠，桌面 App 的会话一开就是好几天，“同时 6 个”明显虚高。改成 30 分钟时间片后，结果更接近实际的并行习惯。
- D1 起初阈值是 90%，Claude Code 的 Opus 占比 79% 会判“做对了”。这和三周体检报告的人工判断（“84% 用 Opus，简单的活也用最贵的”）不一致，所以降到 75%，判定也只给“没用上”（0.3 分），不给“用错了”。
- 三周体检报告里“子代理 0 次”“权限全是 auto”在三周窗口内复核属实。换成全部保留的历史，结论会变（子代理 155 次、bypassPermissions 549 条），所以报告必须写明窗口。

**2026-10-26 第二轮（报告价值审查）**：

- C1 起初把所有出现过的目录都算项目，Codex 有 36 个，其中大半是 Codex App 每次对话自动建的日期目录和只发过 1 条消息的自动任务目录，覆盖率被压低，“去哪儿跑 /init”也说不清。改成只看常用项目，并列出具体是哪几个。
- A2 的结论没变，但补了证据：Codex 128 次压缩里，13 个跨天会话贡献了 66 次。所以处方的第一条改成“第二天就 /new”，而不是泛泛的“少压缩”。
- B4 原来判“没用过 /rewind”，但双击 Esc 回退不留记录，这个结论统计不出来。改成只看会不会及时打断。
- C6 的 Codex 处方原来是改 config.toml，但用户的配置文件里没设权限，87% 的完全放开来自 App 的权限菜单。改成先指向 App 菜单（Approve for me），CLI 再改配置；并按安全优先级排到改进清单第一位。
- /btw 这类小功能不再单独占一张卡（原 A6），改进“功能雷达”统一展示用了几次。

**2026-10-27 第三轮（降噪 + 结果信号，v0.1.2-beta）**：

- 发现并修了一个计数问题：Codex App 会把文件清单、内置浏览器状态、对 Agent 提问的界面回答包进用户消息。现在只取 `## My request:` 之后的真实文字，纯注入块跳过，界面回答记为“Agent 向你提问”。Claude 桌面版的“应用被退出，请继续”提示也不再算用户消息。
- 返工识别从“消息以‘不对’开头”改成更宽的说法列表。旧规则在作者 1500 多条消息里只认出 2 条；新规则认出约 50 条，抽样准确率约八成。
- 作者数据上：Claude Code 每 100 条 3.0 次、后半段在变好；Codex 每 100 条 3.8 次、后半段从 2.0 升到 6.3。一次做对的会话两边都在 65%–68%，略低于 70% 的线，和 `/insights` 报告里摩擦不少的结论一致。
- B6、D3 移到功能雷达；B3、B4、D1 不计分。D 区只剩缓存命中率，权重降到 10%。
